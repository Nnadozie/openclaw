Rule (Sauki discipline + the 2026-09-10 discipline update): a feature counts **✅ only if** the
contract is **implemented**, **invoked on a real production path (file:line)**, **covered by a test**,
**PROVEN AT RUNTIME** (a gate that _executes_ the path, not static grep), and **carries a named gate**
that proves it. Type-only / dead (factory-present-but-unimported) code = 🟡 at best; not built = ❌.
Static-grep-only proof is 🟡 even if the impl is wired — presence ≠ behaviour.

**Legend:** ✅ = impl + prod-wired + tested + runtime-proven + named gate · 🟡 = impl(+test) but NOT
runtime-proven (no executing gate) or not functionally wired · ❌ = not built / type-only / dead.
**Static-only proofs are reported honestly as 🟡 in the `Runtime-proven?` column** even where the
"wired" column shows a real call-site.

## Method (how this was derived — reproducible)

Mined from the real source, not the docs: `grep -rn "@fork-seam" src/fork/**` (seam inventory);
`grep -rn "create*Seam|applyForkRuntime" src --include=*.ts` excluding `src/fork/**` and `*.test.ts`
to find **production call-sites**; `find src/fork -name "*.test.ts"` + `grep -cE "^\s*(it|test)\("`
for test counts. Result: two non-fork production importers — `src/gateway/server-reload-managed.ts`
(U1/U11 via `applyForkRuntime`) and `src/agents/embedded-agent-runner/run/model-setup.ts` (U6 via
`applyRunNodeModelSelection`) — plus the transitive closure through `src/fork/index.ts`/`runtime.ts`
which now reaches U5, U6 (`createNodeModelSeam`), and U12 after this commit's wiring.
The **Gate** column names the CI script + gate that proves (or fails to prove) each seam — updated to
distinguish _runtime_ proof from _static_ proof per the 2026-09-10 discipline update, and Gate 2 now
computes **transitive reachability** (following fork-internal imports) rather than a literal name grep.
