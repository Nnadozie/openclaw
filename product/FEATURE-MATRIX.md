## Top ❌ / block gaps (the op+ fix list)

1. **U5 / U6 / U12 are dead code in production.** Their `create*Seam` factories are exported but
   **never called** (not by the gateway, not by `src/fork/index.ts`; U12 has no call-site at all).
   Only `applyForkRuntime` (U1+U11) reaches a running path. Fix: wire U5 into the heartbeat/cron
   service, U6 into the launch model-picker path, U12 into the upstream tracker — each with a
   production call-site (`file:line`) + a runtime-invocation test (the `runtime.test.ts` pattern).
2. **U2 is constructed on the prod path but inert.** `createForkSeams` reaches it (transitively
   wired) but passes fail-closed no-op `stage`/`apply` deps whose `validate` always refuses — so the
   self-upgrade loop can never actually act in production. Wire real stage/apply deps from the gateway
   runtime, or U2 is "present but non-functional" (honest 🟡).
3. **U3 / U4 / U7 / U8 / U9 / U10 / U13 have no code at all** — zero impl, zero test, zero wiring.
   They are spec (UPGRADES.md) only.
4. **No CI.** The fork has zero mechanical verification — nothing typechecks/builds/tests off-box.
   Filled by `.github/workflows/ci.yml` + `scripts/ci/fork-coverage-guard.sh` (this commit).

## Method (how this was derived — reproducible)

Mined from the real source, not the docs: `grep -rn "@fork-seam" src/fork/**` (seam inventory);
`grep -rn "create*Seam|applyForkRuntime" src --include=*.ts` excluding `src/fork/**` and `*.test.ts`
to find **production call-sites**; `find src/fork -name "*.test.ts"` + `grep -cE "^\s*(it|test)\("`
for test counts. Result: exactly two production call-sites, both in
`src/gateway/server-reload-managed.ts` (U1 + U11). All other seams are factory-only.
